# Product Direction

This document explains the current expansion direction for Avenra UI.

The product is not being grown by random component count. It is being grown by pushing one credible surface area at a time.

## Current completed foundation lines

The repository has already established several meaningful lines:

- foundation component wave
- docs adoption entrypoints
- stable surface governance
- form experience hardening
- selection consistency polish
- overlay and feedback polish
- documentation reliability hardening
- high-frequency input expansion through `TagInput`, `MultiSelect`, and `DatePicker`

## Current expansion philosophy

Avenra UI is prioritizing:

1. high-frequency product interfaces
2. clear support governance
3. documentation that keeps pace with the package
4. coherent component groups instead of isolated one-off wins

## Near-term direction

The near-term direction is:

- deepen high-value input surfaces
- continue making current groups feel product-grade
- move from single-value input maturity toward stronger multi-value and date-entry maturity
- expand only when the current line has real docs, tests, and support clarity

## Why this matters

The fastest way to look large is to keep adding names to a component list.

The fastest way to become a serious library is different:

- make each line credible
- keep docs and exports aligned
- expand in ways that compound the value of what already exists

That is the current product direction for Avenra UI.
